# LightBox 設計メモ

[English](DESIGN.md) · **日本語** · [← README](../README_JP.md)

CH32V003 による LED 調光器。設計上の判断とその根拠を残す（第三者が再現できるように）。
電池/低電力・LEDドライバの判断は [POWER_AND_DRIVER_JP.md](POWER_AND_DRIVER_JP.md) に別記。

## 要求
- 入力: ローカル接続のロータリーエンコーダ
- 出力: シングル PWM（LED 1ch）
- MCU: CH32V003
- 16bit タイマを使用
- **人間の目が感じる明るさ（知覚感度）を最優先で再現** → CIE 1931 L* を採用
- n ms 以内に同方向 j 回以上のクリックで duty=100%/0% に即セット（config で n,j）
- エンコーダの CW/CCW 2 タイプに両対応（config で切替）
- 電源再投入後に明るさを記憶（フラッシュ寿命を延ばすウェアレベリング／初回0／5秒後保存）
- 温度警告灯（フェイルセーフ, config で閾値）
- WS2812/SK6812 常夜灯（暗い時に CIE 基準で呼吸, config で色/色順/周期）
- 上記の設定値は **config.h** に集約

## ピン割当の根拠
最小パッケージ **SOP8 (J4M6)** で成立させる。使えるのは PA1/PA2/PC1/PC2/PC4 の 5 本
（PD1 は SWIO=書込/printf のため温存、VDD/VSS を除く）。

- PWM 出力は **TIM2_CH2 (remap1) = PC2** を採用。姉妹プロジェクト FanConCH32V003 で
  実機実証済みの経路で、リスクが最も低い。
- 残りからエンコーダ A=PA1 / B=PC1 / SW=PA2 を割当。全て内部プルアップ入力。
- PC4 は予備（将来の 2ch 目やステータスLEDに）。

より大きなパッケージでも同じ割当がそのまま使えるため、SOP8 基準で設計。

## エンコーダのデコードとチャタリング吸収
機械式エンコーダの接点は開閉時に必ずバウンス（チャタ）する。**単純 delay で固める方式は
却下**（ループを止めて他処理/取りこぼしが悪化、かつ delay 中のバウンスは吸収できない）。
代わりに「**状態機械 + 時間ロックアウト**」で構造的に吸収する。

### 検討した処置（列挙）と採否
| # | 処置 | 効果 | 採否 |
|---|------|------|------|
| 1 | 遷移テーブルで無効遷移(2bit同時変化)棄却 | ノイズ的グリッチ除去 | 状態機械に内包 |
| 2 | **フルステップ状態機械 (Ben Buxton方式)** | ディテント間の"正しい遷移経路"を完走時のみ1発火。途中バウンスは中間↔静止を往復するだけで発火せず、単相バウンスを構造的に無視 | **採用(主軸)** |
| 3 | **方向反転ロックアウト (既定5ms)** | 直前と逆方向のステップが極短時間に来たら物理的にあり得ない=バウンスとして破棄。同方向は制限せず高速回転を妨げない | **採用** |
| 4 | 定周期サンプリング(例1ms) | サンプル間の高速バウンスを不可視化 | 不採用: 粗いと高速回転でステップ取りこぼし。#2+#3で取りこぼし無く十分 |
| 5 | 各相の多数決積分(N回一致) | 相ごと独立デバウンス | 不採用: #2と役割重複 |
| 6 | ステップ間リフラクトリ(最小間隔) | 一般形 | #3(反転限定)に縮小採用。全方向に効かせると高速回転を殺す |
| 7 | 単純 delay | ─ | **却下**（応答性/取りこぼし悪化・そもそも吸収にならない） |
| 8 | 押しSWの時間ベース積分デバウンス | ループ回数依存の粗いカウンタ廃止 | **採用** |

### (2) フルステップ状態機械
列 index = 現在の2相 `(A<<1)|B`（静止=0b11）。状態は START から始まり、CW 側/CCW 側それぞれ
BEGIN→NEXT→FINAL の経路を**正しい順で完走**した時だけ `DIR_CW`/`DIR_CCW` を1回出す。
バウンスで途中の相が戻っても状態が BEGIN↔START を往復するだけで発火しない。
ハーフステップ品用の表も用意し `ENC_HALF_STEP` で選択（未使用側は `#if` で不コンパイル）。
- ホスト検証: クリーン CW×3→[1,1,1] / CCW×3→[-1,-1,-1]、各遷移にバウンス挿入した1ディテント→[1]
  のみ、CW直後の逆方向ジッタ→[1]のみ（誤反転ゼロ）を確認。

### (3) 方向反転ロックアウト（ユーザ要求の中核）
「5ms 以内に順逆が出現しない」を直接実装。状態機械が万一境界で反転を出しても、直前に**確定した**
ステップと逆方向で、経過が `ENC_REVERSAL_LOCK_MS`(既定5ms) 未満なら破棄する。人が実際にディテントを
逆回しするには数十 ms 以上かかるため、5ms 以内の反転は確実にバウンス。**同方向は無制限**なので
勢いよく回す（スナップ）操作は妨げない。時間は SysTick 実時間（符号なし減算でラップ安全）。

### (8) 押しSW デバウンス（時間ベース積分）
生読みが変化したら候補+時刻を更新し、同じ値が `SW_DEBOUNCE_MS`(既定20ms) 継続したら確定。
確定した押下(立下り)で ON/OFF トグル。ループ回数依存の旧カウンタ方式を廃した。

ポーリングにした理由: エンコーダは手回しで速くても quarter 数 ms 程度。メインループのポーリングで
取りこぼさず、割込みより単純・バグりにくく、SOP8 の EXTI 資源も温存できる。

## 調光カーブ — CIE 1931 L*（人間の知覚を最優先で再現）
最優先要求は「**人間の目が感じる明るさの再現**」。人間の明度知覚は輝度に対し純対数ではなく
**べき乗則（≒立方根, Stevens）**で、暗部は緩やか・明部は急峻。これを標準化した知覚均等スケールが
**CIE 1931 L\***。log/指数テーパでも「暗ゆっくり・明急峻」の形は出るが、特に暗部の感度が実際の
知覚とずれる。忠実再現を最優先するので L* を採用した。

段 i を明度 L*(0..100) に**等間隔**に割り当て（＝1クリック=知覚的に等量の変化）、
L* → 相対輝度 Y → duty に逆算する:

```
L* <= 8 : Y = L* / 903.3            (真っ暗付近の直線トウ)
L* >  8 : Y = ((L* + 16) / 116)^3   (べき乗則)
duty = PWM_TOP * Y
```

- **整数演算のみ**（CH32V003 は FPU 無し）。L* を 1/100 単位で持ち、立方項だけ起動時に
  `uint64` で計算（`PWM_TOP * (L*+16)_x100 ^3 / (11600)^3`）。最大 65535×11600³ < 2^63 で収まる。
  → **libm/float 完全不使用**（float 版よりコードも小さい）。
- 直線トウ（L*<=8）が真っ暗付近を担い、log の「暗部を潰しすぎる」問題を避ける。
- LUT は起動時に 1 回だけ生成。ループ中は `uint16` テーブル参照のみ。
  検算: 端点 0→PWM_TOP、単調増加、重複段ゼロ、低輝度側が知覚的に均等（duty=0,7,14,21,28,…）
  をホストで確認済み。
- 曲線は**固定・パラメータ無し**（L* は知覚均等になるよう定義された曲線そのもの）。
  もし後日「もっと暗部を伸ばす／浅くする」等が要れば、L*→duty の前段にガンマ係数を1つ足すだけで
  調整できる（現状は忠実再現を優先し素の L*）。

## PWM の分解能・周波数（16bit タイマ）
- TIM2 は **16bit カウンタ**。`PWM_TOP` は最大 65535 まで設定でき、`config.h` で可変。
- 既定 `PWM_TOP=4095(12bit), PSC=0` → 48MHz/4096 ≒ **11.7kHz**。可聴域外・目視フリッカ無し、
  かつ対数テーパの低輝度側（duty=数カウント）でも段が潰れず分離する
  （8bit=256 だと最下段が同一 duty に丸まってしまう）。さらに滑らかにしたいなら 8191/16383 へ。

## 高速回しスナップ（duty 100%/0% ショートカット）
「一気に最大／最小にしたい」を、勢いよく回すジェスチャで実現する。

- 同方向クリックの時刻を直近 `SNAP_CLICKS` 個だけリングバッファに保持。
- 新クリックで、その j 個の所要時間 `now - 最古` が `SNAP_WINDOW_MS`(=n ms) 以内なら発火し、
  明るい方向なら `level=LEVELS`(=100%)、暗い方向なら `level=0`(=0%) に即セット。
- 時間基準は SysTick（`SysTick->CNT` / `Ticks_from_Ms`）。符号なし減算でラップ安全
  （窓 0.5s ≪ 32bit ラップ周期 ~715s）。
- 発火後はカウンタをリセットして連続スナップを抑止。`SNAP_WINDOW_MS`/`SNAP_CLICKS` は config。

## エンコーダ CW/CCW 両対応
品種・配線で A/B の位相関係が逆になり、回す向きと増減が反転することがある。
配線し直さず `ENC_REVERSE`(config, 0/1) でデコード方向を反転して吸収する
（デコード後の方向 `dir` を符号反転するだけ。スナップ方向にも一貫して効く）。

## LED 駆動
- 推奨は **MOSFET ローサイドスイッチ**（2N7002 / AO3400 等）。CH32V003 のピン電流
  （Imax ≈ 8mA）に縛られず、明るい LED / 複数直列 / 定電流ドライバも駆動できる。
- 小信号 LED なら PC2 直結（直列抵抗経由）も可だが電流厳守。

## ソフト ON/OFF（押しSW）と動作オプション
押しSW 短押しで出力を ON/OFF トグル。OFF 中もレベルは保持し、再 ON で元の明るさへ。
デバウンスは時間ベース積分（上記(8)）。

- **WAKE_ON_TURN(既定1)**: OFF 中にエンコーダを回すと自動点灯。これが無いと OFF 中の回転は
  隠れた level だけ動いて LED が暗いまま＝無反応に見えるため、既定で有効にした。
- **DEBUG_LOG(既定0)**: printf は開発時専用。理由は下記「ログI/Oをホットループから排除」。

## ログ I/O をホットループから排除（DEBUG_LOG）
再検討で見つかった弱点: 旧実装は毎ディテントで printf していた。ch32fun の debugprintf は
**ブロッキング**で、(a) SWD ホスト未接続だと出力バッファが埋まり処理が停滞、(b) 接続時でも1回が
数百µs〜数ms かかり、その間にエンコーダの A/B 遷移が進むと **quarter を取りこぼして detent を落とす**
（＝高速回転が必要なスナップ機能を自ら阻害）。対策として全ログを `DEBUG_LOG` でコンパイル時ゲートし、
既定 0 では printf 機構ごとリンクしない → ホットループは I/O ブロック無しの最速ポーリング。
Flash も 4380→2968B に減。

## 明るさの不揮発記憶（ウェアレベリング）
電源再投入後に最後の明るさを復元する。フラッシュには**消去回数寿命**があるため、
「同じ番地を毎回 消去→書込」ではなく、消去済み領域へ**追記**し満杯時だけ消去する（循環）。

### フラッシュ物理則（CH32V003 標準モード）
- ビットは **1→0 のみ**書込可。0→1 に戻すには消去が必要。
- **消去単位 = 1KB**（`PER`）。**書込単位 = 2バイト**（`PG`, ハーフワード）。
- 消去済み = 0xFFFF。

### 採用方式：単一セル追記ログ（last-written-wins）
- 末尾 `STORE_SIZE_BYTES`(=2KB) を専用領域として **1KB整列の const 配列**で予約
  （初期値 0xFFFF）。1KB整列かつサイズ=1KBの倍数なので、この領域は**専用セクタ群を
  丸ごと占有**し、消去がコード/定数へ波及しない（実ビルドで g_store@0x1400、
  専用セクタ5–6を占有・コードは〜0x1400 で分離、を確認）。
- **保存** = 先頭から最初の空(0xFFFF)セルへ 2バイト書込（追記）。**1保存=1書込**。
- **現在値** = 先頭から見て最初の空セルの「手前」= 最後に書いた値。空なら 0（初回）。
- **満杯** = 2 セクタ消去して先頭から再利用（循環）。
- レベルは 0..64 で 0xFFFF と衝突しないため、値そのものを 1 セルに格納できる。
- フラッシュコントローラは 0x08000000 ベースの物理アドレスを要求するので、g_store の
  オフセットを 0x08000000 に載せ替えて読み書きする（ch32fun flashtest に倣う）。

### 保存タイミング（書込回数の最小化）
`STORE_COMMIT_MS`(=5秒) の間 明るさが変化しなくなってから **1回だけ**書く。回すたびには
書かない → 調整1セッション=1書込。実際の物理書込を激減させる。

### 寿命の見積り
- 2KB / 2バイト = **1024 レコード**。消去は 1024 保存に 1 回だけ
  → 消去回数を **約 1/1024** に削減 → フラッシュ寿命 **約1024倍**。
- 例: フラッシュ消去寿命を E 回とすると、素朴方式=E 保存、本方式≈ 1024×E 保存。
  E=10,000 なら約 **1000万回**保存可（要データシートで E を確認）。
- ホスト検証: 初回=0、各保存→復元一致、N セル満杯で循環消去、を確認。

### ユーザ提案との対応
ユーザ案は「マーカ(0x0000)＋値」の2セル方式で、更新時に旧マーカも書き換える。目的
（追記＋満杯時のみ消去で寿命延伸）は同じだが、本実装は**単一セル追記**に簡略化した：
- 1保存が **1書込**（案は マーカ＋値＋旧無効化で最大3書込）→ 書込が 1/3 で更に長寿命。
- 2KB で **1024** レコード（案の2セル=512 の倍）。
- 「先頭から最初の空の手前が最新」で一意に復元でき、マーカ／無効化書込が不要。
厳密に案どおりの2セル方式が必要なら容易に切替可能。

### 循環境界の電源断（保留）
満杯→全消去→先頭書込の間(約6ms/1024保存に1回)に電源断すると、その1回の設定が失われうる
（明るさは非致命的なので許容）。厳密化はセクタ ping-pong（新セクタに書いてから旧セクタ消去）。

## 温度警告灯 — CH32V003 に内蔵温度センサが無い問題
再検討で判明: **CH32V003 は内蔵ダイ温度センサを持たない**（ADC ch8=Vrefint / ch9=Vcalint のみ、
温度チャンネルは未定義）。当初 ch8 を温度として読む実装はバグ（無意味な値）だった。
ユーザ意図が「制御MOSFETへのサーマルカップリングで異常発熱を検知」なので、
**外付けアナログ温度センサ(NTC等)を MOSFET に熱結合して ADC で読む**方式に是正。
- `funAnalogInit()/funAnalogRead(ch)` を使用。ADCCLK≤14MHz にするため HCLK/8(6MHz)へ分周。
- 換算は近似1次（NTC は動作点付近を線形近似）。閾値+ヒステリシスで警告 GPIO を駆動。
- 任意で過熱時に本体 PWM も 0 クランプ（`WARN_TEMP_CUT_OUTPUT`）。

## WS2812/SK6812 常夜灯
本体が完全に暗い(`!g_on || level==0`)ときだけ、CIE 基準(cie.h 共用)で 明→暗 を三角波×CIE で
1往復し、その後インターバル完全オフ、を反復。色/色順/RGBW を config 化。
- ws2812b_simple.h(ch32fun) を使用。これが **SysTick=HCLK(48MHz)** を要求するため
  funconfig.h で `FUNCONF_SYSTICK_USE_HCLK 1`。時間ロジックは全て `Ticks_from_Ms` 経由で
  自動追従（SysTick 32bit は 48MHz で約89s ラップ、全ウィンドウ≪89s で安全）。
- 色順(GRB/RGB/GRBW/RGBW)はパック時にバイト順を切替。RGBW系は W チャンネルも CIE で明滅。

## バグ洗い出しの記録（このイテレーション）
- **[修正] 内蔵温度センサ不在**: ch8 は Vrefint。外付けセンサ方式へ是正（上記）。
- **[修正] WS_MAX_COLOR 桁不整合**: 既定 GRB(6桁)に対し 8桁(RGBW)値でバイトずれ → 6桁に修正、
  RGBW は別例として明記。
- **[追加] 静的アサート**: STORE_SIZE_BYTES%1KB、LEVELS<0xFFFF、SLOPE≠0、PERIOD≥2、WS_COUNT≥1。
- **[検証] ストア最終値 0x0000**: 0x0000(消灯)≠0xFFFF(空) で正しく復元。境界網羅テスト全合格＝バグ無し。
- **[検証] 条件コンパイル**: 全機能ON/OFF・RGBW・ハーフステップの各組合せで警告ゼロ。
