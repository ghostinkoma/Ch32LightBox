# LightBox 仕様書 (SPEC)

[English](SPEC.md) · **日本語** · [← README](../README_JP.md)

CH32V003 LED 調光コントローラの機能仕様。設計判断の根拠は [DESIGN_JP.md](DESIGN_JP.md)、
設定項目は [CONFIG_REFERENCE_JP.md](CONFIG_REFERENCE_JP.md)。

## 1. 対象・構成
- MCU: CH32V003（推奨パッケージ **F4P6 TSSOP20**。SOP8 はコア機能のみ）
- フレームワーク: ch32fun（自己完結）
- クロック: HCLK 48MHz、SysTick=HCLK（48MHz）※WS2812 ドライバ要件
- 入力: ロータリーエンコーダ(A/B + 押しSW)、外付け温度センサ(NTC等)
- 出力: 本体 PWM 1ch(LED)、温度警告 GPIO、WS2812/SK6812 常夜灯

## 2. 調光カーブ（CIE 1931 L*）
- 段 i(0..64) を明度 L* に等間隔割当 → L*→輝度Y→duty 逆算（1クリック=知覚的に等量）。
  - `L*≤8: Y=L*/903.3`（直線トウ） / `L*>8: Y=((L*+16)/116)^3`
- 整数演算のみ（立方は uint64）、libm/float 不使用。本体と常夜灯で共用（`cie.h`）。

## 3. PWM 出力
- TIM2_CH2(remap1)=PC2、16bit カウンタ。既定 `PWM_TOP=4095`（≈12kHz）。最大 65535。
- **出力ピンは `PWM_PIN` で選択可**（既定 `PC2`=TIM2_CH2。他に `PC1`=TIM2_CH4 / `PA1`=TIM1_CH2 / `PC4`=TIM1_CH4）。`source/pins.h` がタイマ/チャネル/remap を導出しコンパイル時に検証。実機検証済は `PC2` のみ、他はコンパイル対応。

## 4. エンコーダ / チャタリング吸収
- フルステップ状態機械(Ben Buxton)。正しい遷移経路を完走時のみ ±1 発火 → 単相バウンス構造吸収。
- **方向反転ロックアウト**: 直前と逆方向のステップが `ENC_REVERSAL_LOCK_MS`(既定5ms)以内なら
  物理的にあり得ない=バウンスとして破棄。同方向は無制限（高速回しを妨げない）。
- ハーフステップ品対応(`ENC_HALF_STEP`)、CW/CCW 反転(`ENC_REVERSE`)。
- 高速回しスナップ: `SNAP_WINDOW_MS` 内に同方向 `SNAP_CLICKS` 回で 100%/0%。
- 押しSW: 時間ベース積分デバウンス(`SW_DEBOUNCE_MS`)、短押しで ON/OFF。

## 5. 明るさ不揮発記憶（ウェアレベリング）
### 方式
- `STORE_SIZE_BYTES`(既定2KB) を 1KB整列 const 配列で専用予約。単一セル追記ログ(last-written-wins)。
  ※配置は「Flash末尾」ではなくリンカ任せ(コード直後)。だが **1KB整列 かつ サイズ=1KBの倍数**
  なので専用セクタを丸ごと占有し、消去が他データに波及しないことは**位置に依存せず保証**される
  （const オブジェクト=リンカが排他確保、実測でも同セクタ内は g_store のみ）。
  ※アドレスはファーム容量で変わりうる／保存データはバイナリに0xFF初期値として含まれ再書込で消える
  （ファーム更新をまたいで残すには別途リンカスクリプトで固定領域を確保する必要あり）。
- 保存 = 先頭から最初の空(0xFFFF)へ 2バイト追記（1保存=1書込）。現在値=最初の空の手前。
  満杯で 2 セクタ消去し循環。初回(全0xFFFF)=OFF/明るさ0。
- **ON/OFF も保存**: 1セルに `bit15=ON, bit0..6=level` をパック（最大0x8040, 空0xFFFFと非衝突）。
  → 電源を切った(OFF)状態も記憶し、次回投入時に OFF で復帰する。
- 保存タイミング: 状態(ON/OFF+level)が `STORE_COMMIT_MS`(5秒)変化しなくなってから 1回だけ。
  ※5秒未満で電源断すると直前の変更は未保存（フラッシュ摩耗を抑える遅延書込の仕様）。

### フラッシュ寿命（データシート上の想定設定回数）
- CH32V003 フラッシュ消去寿命 ≈ **10,000 回/セクタ**（WCH データシート値。実機で要確認）。
- 2KB / 2バイト = **1024 レコード**／消去。よって:

  **想定保存回数 ≈ 1024 × 10,000 = 約 10,240,000 回（約1000万回）**

- **判定**: 10万回を大きく上回る（約100倍以上）。→ **現状の 2KB でフラッシュ増設は不要**。
  - 仮に消去寿命が 1,000 回でも 1024×1000 ≈ 102万回で 10万超。
  - さらに「5秒後に1回だけ書込」で実書込は1調整セッション=1回に圧縮され、実運用の
    消費はこの理論値よりずっと少ない。
- 記録数を増やしたい場合のみ `STORE_SIZE_BYTES` を 1KB 単位で増やす（4KB=2048レコードで倍）。

### 最終値 0x0000 の扱い（境界）
- レベルは 0..64 で **0x0000(=消灯) は有効値**、空セルは 0xFFFF。両者は別物なので
  「最終値が0」でも正しく復元される。ホストで境界網羅テスト済（単発0/連続0/最終セル0/
  0とnonzero交互/満杯循環後0 — 全て復元一致）。**この件のバグは無し。**

## 6. 過熱フェイルセーフ（強制遮断＋サーマルスロットル）
> **★現状 既定OFF（`TEMP_PROTECT_ENABLE 0`）**。当初のダイ温度「推定」は実測でないため
> 全開時に推定値だけで閾値を超え、点けっぱなしで**急に消灯する誤遮断**が実機で発生した。
> → ダイ推定は**不採用**。本当に発熱保護が要る場合のみ、外付けNTC実測(6.2)で有効化する。
> 以下は機能の仕様として記載（有効化した場合の動作）。

温度源を 2 種から選択（`TEMP_SOURCE`）:

### 6.1 ダイ温度「推定」（不採用・参考）
- ★**CH32V003 に内蔵ダイ温度センサは無い**（ADC ch8=Vrefint / ch9=Vcalint のみ）。
  実測できないので **熱モデルで推定**する（「おおよその値／28℃からの上昇分」で十分という前提）:
  - `T_target = DIE_AMBIENT_C(28℃) + (実効duty/PWM_TOP) × DIE_RISE_AT_FULL_C(60℃)`
  - `T_est` は時定数 `DIE_TAU_MS` で `T_target` に一次追従。
  - 実効デューティ（遮断/スロットル反映後）を入力にするので、遮断すれば推定も下がり再開する。
- 外付け部品ゼロ。値は目安（`DIE_RISE_AT_FULL_C` を実機の発熱に合わせ調整）。

### 6.2 外付けアナログセンサ（実測・要ピン）
- NTC 等を制御MOSFETに熱結合し ADC(`TEMP_SENSE_PIN`。ADCチャネルは自動導出)で実測。近似1次校正 `TEMP_CAL_*`（要校正）。

### 6.3 保護動作（両ソース共通）
- `WARN_TEMP_C`(80℃)超 → **本体PWM(MOSFET)を強制的に0**（火災リスク回避）。
- `WARN_TEMP_HYST_C` 下がって再開。
- **サーマルスロットル**: 遮断→再開を `THERMAL_TRIP_N`(n)回繰り返すごとに、最大出力を
  `THERMAL_THROTTLE_PCT`(j)% ずつ累積ダウン（上限 `THERMAL_THROTTLE_MAX`）。
  → 過熱を繰り返す環境では自動的に出力が下がり、いずれ定常温度が閾値未満に収まって安定。
  （ホスト検証: 全開→80℃遮断→72℃再開を3回→20%ダウン→実効80%→定常76℃で以後トリップ停止。）
- 任意で警告灯 `WARN_LED_ENABLE`（過熱中 High）。

## 5b. ソフトスタート（フェードイン/アウト）
- 電源(押しSW)ON/OFF 時、および起動(電源投入)時に、設定輝度まで滑らかにフェード。
- **明度 L*(知覚量)を時間に対し線形補間**し、各点を CIE で duty 化 → 目で見て均等な変化。
  （duty は暗部で細かく明部で粗く変化＝知覚リニア。ホスト検証: L*時間差分ほぼ一定。）
- `SOFT_START_ON`/`SOFT_START_OFF`(ms, 0=即時, 最大65535≒65.5s)。ON/OFFで別指定。
- エンコーダ操作は即応（ソフトスタート対象外）。フェード中の再トグル/回転は現在輝度から
  滑らかに目標へ追従（ジャンプしない）。押しSWチャタは時間ベースデバウンスで吸収。
- 常夜灯はフェード完了で輝度0になってから開始（フェード中は点かない）。

## 6b. ウォッチドッグ（IWDG）
- ファーム暴走時に自動リセットで復帰。`WDT_TIMEOUT_MS`(既定2000ms、約2〜8190ms)。
- LSI(≈128kHz)/256 駆動でタイムアウトは概算。メインループ先頭で毎周リフレッシュ。
- 最悪ブロック（フラッシュ書込 数ms 等）よりタイムアウトが十分長いことを確認済み。
- ※`DEBUG_LOG=1` かつ SWD ホスト未接続だと printf 停滞で WDT リセットしうる（開発時の注意）。

## 6c. EMI 対策（大電流LED向け）
- **スルーレート制御**: PWM 出力ピンの GPIO 速度 `PWM_SLEW_MHZ`(2/10/30) を下げてエッジを鈍らせ
  高調波を低減（大電流は 2MHz 推奨）。
- **スペクトラム拡散**: `PWM_SPREAD_SPECTRUM=1` で ATRLR を `±PWM_SPREAD_RANGE` 微小ディザし
  基本波のピークを分散。duty比は周期に追従させるので **明るさは不変**。`PWM_SPREAD_PERIOD_MS` 間隔。

## 7. WS2812 / SK6812 常夜灯
- 本体が「完全に暗い」（`!g_on || level==0`）ときだけ動作。
- 1周期: `NIGHTLIGHT_PERIOD_MS`(n) かけて CIE 基準で 明→暗 を1往復（三角波×CIE）。
- 周期後 `NIGHTLIGHT_INTERVAL_MS`(i) 完全オフ → 反復。本体を明るくすると即オフ。
- 時間判定は**ms基準で比較**（経過を先に ms 化）。`Ticks_from_Ms(period)=period×48000` の
  uint32 オーバーフロー(period≳89.5s)を回避。周期/間隔は静的に ≤60000ms に制約(SysTick
  32bit ラップ~89.5s の安全マージン)。
- 最大色 `WS_MAX_COLOR`（RGB=0xRRGGBB / RGBW=0xRRGGBBWW）。各chを CIE で明滅。
- チップのバイト並び `WS_ORDER` を GRB/RGB/GRBW/RGBW から選択（製品差を吸収）。
- SK6812 RGBW 対応。データ線 `WS_DIN_PIN`（port/番号は自動導出）、`WS_COUNT` 個。
- 送信は `NIGHTLIGHT_REFRESH_MS` 間隔。ws2812b_simple.h(ch32fun) 使用（SysTick=HCLK 要件）。

## 8. 起動シーケンス
1. SystemInit → GPIO/エンコーダ初期化
2. CIE LUT 生成
3. ストアから前回明るさ復元（初回=0、`g_on=level>0`）
4. PWM 起動（復元値を反映）
5. 温度 ADC / 常夜灯 初期化
6. メインループ（エンコーダ/SW/温度周期/常夜灯/ストアコミット）
